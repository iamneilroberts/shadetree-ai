# Probe and vehicle-variation structure

Date: 2026-10-02. Status: draft for Neil's review. Source of truth stays `docs/design.md`; update it as each step merges.

## Goal
Point the tool at a car it has never seen (Neil's Ridgeline and Highlander, Austin's older cars) and come away with a record of what that car supports, how it answers, and how it differs from other cars. Neil should be able to share that record without sharing the VIN. All of it stays read-only: Modes 01-0A plus the AT/STN identify list. No allowlist change is needed for anything below.

## Done in step 1 (this branch)
- `scan()` now reads Mode 09 `0904` (CAL ID), `0906` (CVN) and `090A` (ECU name), but only the ones the `0900` bitmap advertises, and only on CAN (the same gate as the VIN). Results go into `Snapshot.mode09` {cal_ids, cvns, ecu_names}: one union list per item across all ECUs, first-seen order, not attributed to an ECU because headers are off. Advertised items that get no usable reply produce one warning.
- `scan()` reads `ATRV` and stores it as `Adapter.supply_voltage`. On a genuine STN it also reads `STDI` and stores it as `Adapter.device`. Both are optional fields, so older snapshots still load. `vehicle_info` and the CLI `scan` summary show them.
- Every console run file now has `"transcript": "transcripts/<stamp>-console.jsonl"`, a path relative to the data home, so a run can be traced back to its raw replies. (The hub.py change is about 5 lines in `_reset`, `_run` and `_write_run`; `Transport.transcript_path` exposes the recorder's path.)

## Done in step 2 (reply classification and unknown-PID capture)
- `elm.classify(lines, sid)` returns `ok | no_data | nrc:<code> | wrong_sid | adapter_error | garbled`. It is `ok` exactly when `parse_all` finds a payload (a hypothesis test pins that), so a reply where one ECU refuses and another answers is `ok`. `nrc:<code>` keeps the first matching ECU's code. A `7F` for a different request counts as `wrong_sid`. An empty reply (the adapter printed nothing) is `adapter_error`. `parse_all` is unchanged; `_clean` is shared between them.
- `scan()` wraps the transport. Every OBD request it sends goes into the optional `Snapshot.replies` list as `{cmd, reply, ms}`, where `ms` is send-to-reply time from `time.monotonic`, near 0 in replay. AT/ST commands are not classified. The headers-on `0100` used for ECU discovery is also left out, because headers change the reply layout. Every class other than `ok` and `no_data` produces one warning listing `<cmd> <class>`. NO DATA is recorded but not warned, since unsupported is not an error. As a result, a `7F` reply to `03` now shows in the snapshot and in the warnings instead of looking like "no codes".
- `scan()` reads every Mode 01 PID the bitmaps advertise that `pids.py` cannot decode. It skips bitmap PIDs and `01`, which readiness already reads. Each PID is sent once, as `01<pid>`, after the readiness read and before the freeze frame, and the results go into the optional `Snapshot.undecoded` list as `{pid, reply, raw}`. `raw` holds the data bytes after `41 <pid>`, as hex, one entry per answering ECU in reply order. The list is capped at 32, and the PIDs left out are named in a warning. No decoders were added. On the Ridgeline bitmaps this reads 13 41 66 67 68 6C 9D 9E 9F A3 (test pinned).
- Both fields are optional, so older snapshots still load. `hub.py` and `console.html` are untouched (the hub does not call `scan()`). The synthetic sedan fixture gained one `0113` reply.

## Done in step 3 (probe command and VIN-free report)
- `shadetree-ai probe --port DEV` (live, ATSP0 by default) or `--replay TRANSCRIPT` (no adapter). It runs `scan(..., mode06=True)`: the usual scan plus one Mode 06 MID-bitmap walk (`0600`, `0620`, ... through the same `_walk_pages` as Modes 01/02; CAN only; no test results are read). Advertised MIDs go into `supported_pids["06"]`, and their reply classes and latencies into `replies` like every other request.
- `probe.report(snapshot)` builds the shareable dict and `write_probe` writes `probes/<id>.json` and `probes/<id>.md` (never overwrites). Kept: vehicle key, protocol, adapter, ECU headers, Mode 09 items, bitmaps, replies (class + ms), undecoded raw bytes, warnings. Left out: VIN, VIN serial, transcript path and contents. A warning that mentions the VIN keeps only the text before its colon, because "invalid VIN" and "ECUs disagree" warnings quote it. `write_probe` refuses (writes nothing) if `vin.find_vins` finds a token in the JSON or Markdown. A live probe also saves the normal private `snapshots/` + `transcripts/` pair through `capture()`; a replay probe writes only the report. `probes/` is gitignored (pinned in `test_no_real_vins`).
- `tests/test_probe.py` runs the report on the synthetic sedan and the committed Ridgeline fixture and asserts `find_vins(json + markdown) == []`, that neither the VIN nor its serial appears, and that the vehicle key does (so an empty report cannot pass). The live CLI path is tested end to end through `SerialPort` against a local TCP "adapter" (`elm_server` fixture in `conftest.py`) that answers from transcript records.
- Follow-ups done: `Dtcs.unanswered` (optional) names stored/pending/permanent requests with no usable answer, mirroring the console's `codes.unanswered`; `read_dtcs` returns the requested kinds among them, and the CLI `scan` summary prints "no answer" for them. The CLI `scan` summary and `vehicle_info` show reply-class counts and the undecoded-PID count. `export-run` pairs a run with the transcript its `transcript` field names (relative to the data home; a path outside the home or a missing file pairs with nothing rather than a guess), and falls back to the timestamp pairing only when the field is absent.

## What the real Ridgeline bitmaps say (tests/fixtures/ridgeline_2024_can29.jsonl, 2 responding ECUs; headers off, so "first"/"second" is reply order, assumed stable across pages)
- Mode 01, first responder: 01 03 04 06-09 0B-0E 11 13 15 19 1C 1F 21 23 24 28 2C-31 33 3C 3D 41-44 47 49 4A 51 55-58 62 63 66 67 68 6C 8E 9D-9F A3 A6. Second: 01 04 05 0C 0D 11 1F 21 30 31 33 41 42 45 47 49 4A.
- The truck does not advertise 0F (IAT), 10 (MAF), 46, 5C or 5E. If the example run is the same truck, it did not skip those PIDs; the truck never offered them. It advertises 66/67/68 (MAF, coolant and intake-air sensors A/B) instead, and `pids.py` cannot decode those. So the most useful "unknown PID" work on this truck is 66/67/68, not a long tail.
- Mode 09: the first ECU advertises 02 04 06 08 0A 13 14 16-19 and page 20. The second advertises 04 06 0A, so both should answer CAL ID, CVN and ECU name. Not yet checked on the real truck.

It writes `probes/<stamp>.json` and a short Markdown summary. The shareable form leaves out the VIN, the VIN serial and the full transcript. It keeps the vehicle key (WMI + VDS + year char; it names a class of car, not one car), protocol, adapter, ECU names, CAL IDs/CVNs (they are calibration versions shared by every car with that software, not per-car), the bitmaps, reply classes and latencies. Add a test like `test_no_real_vins` that runs the report on the synthetic fixtures and asserts `vin.find_vins(report) == []`.
4. ~~**Quirks file keyed by vehicle key / WMI**~~: built (`quirks.py`, `probe.propose_quirks`, `shadetree-ai quirks accept`; see `docs/design.md` §6). Original plan (~5 h): `quirks/<key>.json`, falling back to `quirks/<WMI>.json`: hints only, schema-validated (malformed means "no quirks", like `profiles.py`). Fields: `pids_lie` (advertised but always NO DATA), `max_hz`, `protocol` (ATSP pin), `ecus` (header → role), `notes[]`, each with `source`, `confidence`, `verified`. The probe *proposes* entries from what it saw (classes and latency). A person accepts them, and nothing is written automatically. Load the file in `session.connection` / the hub run as a hint, never as a decision. Per-vehicle watch ranges come after this.

## Out of scope here
Legacy-bus decode (needs Austin's transcripts first), per-ECU attribution of Mode 09/DTC replies (needs a headers-on pass per command, and 29-bit header parsing is still unverified on hardware), VIN to make/model decode, Mode 22/UDS (barred).
